# GEO 可见度基线测试 · geo-visibility-baseline

> 📖 **使用说明书：[USAGE.md](./USAGE.md)** —— 安装、触发话术、依赖的付费接口（大模型 / 搜索 API 配置与成本估算）、常见问题、踩坑记录。


一个 Agent Skill：把「做了这么多到底有没有用」变成可验证的实验。

## 它解决什么问题

做 GEO 最常见的困境：改了一堆东西，两个月后有人问「有效果吗」，你只能说「感觉好像好一点」。

因为**没有基线，就无法归因**。你分不清是结构改动的功劳、是新内容的功劳，还是对手恰好掉下去了。

这个 skill 用一条纪律解决它：**固定问题集 + 隔期复测 + 三层归因。**

## 五个步骤

| # | 步骤 | 产出 |
|---|---|---|
| 1 | **建问题集**（一次性，只增不改）| 6-8 个问题，含品类/场景/品牌三类 |
| 2 | **跑基线** | 问题 × 平台矩阵表 |
| 3 | **隔期复测**（≥2 周）| 同格式第二张表 |
| 4 | **三层归因** | 技术层 / 引用层 / 业务层 |
| 5 | **输出** | 基线 vs 本次 vs 变化 三列对照 |

## 四条核心原则

- **问题集固定，建好后不许改。** 改了问题，历史数据全部不可比。
- **必须含品类词。** 只问「XX 公司怎么样」必然命中，等于没测。
- **平台固定，不混着看。** 不同 AI 抓取逻辑不同，混测无法归因。
- **单次结果不下结论。** AI 回答有随机性，看三次以上趋势。

## 一个关键区分（实战踩出来的）

**搜索层 ≠ 模型层。**

| | 搜索层 | 模型层 |
|---|---|---|
| 品牌词 | 能找到官网、公众号、第三方文章 | 可能判定「不认识这个名字」 |
| 品类词 | 看检索结果里有没有你 | 看知识里有没有你 |

真实案例（2026-10-28）：某品牌在搜索引擎里能查到官网与多篇文章，但在模型知识里被判定为「不是一个广为人知的标准通用产品名称，很可能是名称记忆偏差或概念混淆」。

**结论：内容被「索引」不等于被「吸收」。** 两者要分开测，别混着下判断。

## 三层指标与观察周期

| 层 | 指标 | 周期 |
|---|---|---|
| 技术层 | 抓取记录、收录数、Schema 校验 | 1-2 周 |
| 引用层 | 是否被提及、描述措辞、对手名单变化 | 4-8 周 |
| 业务层 | 询盘量、采购级占比、来源结构 | 8-12 周 |

## 红线

- 不许改问题集（要加新问题，另开一轮）
- 不许只测品牌词当成绩
- 单次结果不写进结论
- 差异小于 2 个问题视为噪声
- **不许把「百度收录数」当成「AI 推荐度」**

## 安装

把 `SKILL.md` 放进 skills 目录：

```
~/.openclaw/skills/geo-visibility-baseline/SKILL.md
```

## 配套技能

- `geo-competitor-mining` — 侦察：扒对手结构、出模板、审自家、出修复清单

先用侦察技能决定「改什么」，再用本技能验证「改了有没有用」。
